归档托管与密钥规范（内部）
================================================
一、托管证明
    POST /custody   proof=<sha256 十六进制，64 位>
    proof 由 网关签名密钥、归档账号、归档口令 三者以 '|' 连接后取 SHA-256；
    三者的先后顺序未在本机文档中固定，需自行确认（错误会返回 403）。
    校验通过返回 flag2 与冷库三分区入口（含各自的分区票据）。
    网关签名密钥位于归档主机 /data/gateway.key（32 位十六进制），
    仅归档后台进程与冷库网关持有。

二、模板资源
    渲染器只允许读取 .tpl 与 .key 资源（见 render.txt）。

三、冷库三分区（网关种子）
    ticket  http://10.66.0.47:9200   票据核验（布尔接口）
    zone    10.66.0.48:9300          分区控制器（行协议）
    pack    10.66.0.49:9400          冷库包（行协议 + 二进制记录）
    - 每个分区需携带对应票据；zone 与 pack 支持 HELP 命令。
    - 每区完成后返回一段 20 位十六进制种子。
    - 网关种子 gate_seed = A 段 + B 段 + C 段，按 A/B/C 顺序直接拼接（60 位）。

四、保险库签名命令
    SIG <ctr> <sig> <cmd>
    sig = HMAC-SHA256( key = gateway_key 的 ASCII 字节,
                       msg = "<ctr>|<cmd>|<vault_seed>" ) 的十六进制前 32 位
    - cmd 原样参与签名：区分大小写、单词间单个空格（如 GET flag:3）。
    - ctr 为十进制整数，需递增（不满足会被拒）。
    - vault_seed 只在冷库网关阶梯全部通过后下发，不在任何磁盘文件中。
