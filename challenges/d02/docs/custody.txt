归档托管与密钥规范（内部）
================================================
一、托管证明
    归档在完成一次冷链路交接后，需要用网关签名密钥向本机证明托管资格：
      POST /custody   proof=<sha256 十六进制，64 位>
      proof = sha256( gateway_key + '|' + 'archivist' + '|' + 归档口令 ) 的完整摘要
    校验通过返回 flag2 与冷库三分区入口（含各自的分区票据）。
    网关签名密钥位于归档主机 /data/gateway.key（32 位十六进制），
    仅归档后台进程与冷库网关持有；不要把它复制到其它主机。

二、模板资源
    渲染器只允许读取 .tpl 与 .key 资源（见 render.txt）。

三、冷库三分区（网关种子）
    托管证明通过后下发三个分区入口，各自需要带上对应的分区票据：
      ticket  http://10.66.0.47:9200   票据核验（SQLite 遗留拼接查询，只回布尔结果）
      zone    10.66.0.48:9300          分区控制器（行协议，24 步状态机）
      pack    10.66.0.49:9400          冷库包（行协议 + 二进制记录）
    - 分区票据随请求携带；缺失或错误返回 403 / bad ticket。
    - zone 与 pack 支持 HELP 命令，返回协议与判定规则。
    - 每个分区完成后返回一段 20 位十六进制种子。
    - 网关种子 gate_seed = A 段 + B 段 + C 段，按 A/B/C 顺序直接拼接（共 60 位）。
      任一分区未完成都无法进入冷库网关的阶梯。

四、保险库签名命令
    保险库要求每条命令携带计数器与 HMAC 签名：
      SIG <ctr> <sig> <cmd>
      sig = HMAC-SHA256( key = gateway_key 的 ASCII 字节,
                         msg = "<ctr>|<cmd>|<vault_seed>" ) 的十六进制前 32 位
    - cmd 原样参与签名：区分大小写、单词间单个空格（如 GET flag:3）。
    - ctr 为十进制整数，同一会话内必须严格递增；重放或乱序返回 stale counter。
    - vault_seed 只在冷库网关 24 轮阶梯全部通过后下发，不在任何磁盘文件中。
